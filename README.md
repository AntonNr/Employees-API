# API сотрудников

REST API для управления сотрудниками, их зарплатами и отделами. Позволяет создавать, редактировать, удалять и просматривать записи (одну или списком).

**Стек:** Python, Django, Django REST Framework, PostgreSQL.

Требуется Python 3.12 или новее (проект разрабатывался на Python 3.15).

## Сущности

### Сотрудник (`employees`)

| Поле | Описание |
|---|---|
| `id` | Идентификатор (только чтение) |
| `first_name` | Имя |
| `second_name` | Фамилия |
| `age` | Возраст в годах (не меньше 14) |
| `create_date` | Дата создания записи (только чтение, ставится автоматически) |

### Зарплата сотрудника (`salaries`)

| Поле | Описание |
|---|---|
| `id` | Идентификатор (только чтение) |
| `employee` | `id` сотрудника |
| `salary` | Зарплата в BYN, до двух знаков после запятой (не меньше 0) |

### Отдел сотрудника (`departments`)

| Поле | Описание |
|---|---|
| `id` | Идентификатор (только чтение) |
| `employee` | `id` сотрудника |
| `name` | Название отдела |

## Запуск проекта

### 1. Подготовка

- Установленный Python 3 и PostgreSQL.

### 2. Виртуальное окружение и зависимости

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 3. База данных

1. В PostgreSQL (например, через pgAdmin 4) создать пустую базу данных `employees_db`.
2. В файле `core/settings.py`, в разделе `DATABASES`, заменить параметры на свои: `NAME`, `USER`, `PASSWORD`, `HOST`, `PORT`.

Время хранится в UTC, отображается по Минску.

### 4. Миграции

```bash
python manage.py migrate
```

### 5. Запуск сервера

```bash
python manage.py runserver
```

API будет доступен по адресу `http://127.0.0.1:8000/api/`. Страница корня показывает ссылки на все три эндпоинта, и через неё же можно пробовать запросы прямо в браузере (встроенный интерфейс DRF).

### 6. Панель администратора

```bash
python manage.py createsuperuser
```

После этого админка доступна по адресу `http://127.0.0.1:8000/admin/`.

## Эндпоинты

Для каждой сущности доступны одинаковые операции:

| Метод | Адрес | Действие |
|---|---|---|
| `GET` | `/api/<сущность>/` | Список |
| `POST` | `/api/<сущность>/` | Создание |
| `GET` | `/api/<сущность>/<id>/` | Просмотр одного элемента |
| `PUT` | `/api/<сущность>/<id>/` | Полное изменение (нужно передать все поля) |
| `PATCH` | `/api/<сущность>/<id>/` | Частичное изменение (только изменяемые поля) |
| `DELETE` | `/api/<сущность>/<id>/` | Удаление |

Где `<сущность>`: `employees`, `salaries` или `departments`.

## Примеры запросов

### Создать сотрудника

`POST /api/employees/`

```json
{
    "first_name": "Иван",
    "second_name": "Петров",
    "age": 30
}
```

Ответ `201 Created`:

```json
{
    "id": 1,
    "first_name": "Иван",
    "second_name": "Петров",
    "age": 30,
    "create_date": "2026-11-19T19:42:15.485621+03:00"
}
```

### Создать зарплату

`POST /api/salaries/`

```json
{
    "employee": 1,
    "salary": "1500.50"
}
```

### Создать отдел

`POST /api/departments/`

```json
{
    "employee": 1,
    "name": "Бухгалтерия"
}
```

### Изменить часть полей

`PATCH /api/employees/1/`

```json
{
    "age": 31
}
```

## Коды ответов

| Код | Когда |
|---|---|
| `200 OK` | Успешный просмотр или изменение |
| `201 Created` | Запись создана |
| `204 No Content` | Запись удалена |
| `400 Bad Request` | Некорректные данные (текст ошибки в теле ответа) |
| `404 Not Found` | Записи с таким `id` нет |

## Проверка данных

- `age` не меньше 14.
- `salary` не отрицательная, не более двух знаков после запятой.
- Имя, фамилия и название отдела не могут быть пустыми и не могут состоять только из цифр.
- `id` и `create_date` задаются сервером: если передать их в запросе, они будут проигнорированы.
